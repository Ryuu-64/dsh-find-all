## 先知道当前状态

2026-10-22：196 项自动测试和打包检查已通过。官方 DSH `0.2.0-rc.2` 和 `0.2.1-rc.2` 的隔离 Web 回归均已完成，覆盖下列各自适用的场景；新版使用实际声明支持该版本的候选，通过正常安装流程验证。两个宿主的实测内容与 bundle hash 见[兼容说明](compatibility.md)。PR #36 后续报告：同一候选也通过从官方签名安装器原样解包的 Windows Desktop `0.2.1-rc.2` 验收；未测 Windows 安装器/注册表集成及旧版 Desktop。该报告的详细范围与两条未逐一归因的资源错误见[PR #36](https://github.com/Ryuu-64/dsh-find-all/pull/36)。

兼容范围已加入确切的 `0.2.1-rc.2`，其余原有版本保留。复测时不要使用 `allow-version --accept-risk` 绕过安装检查，不要碰真实会话，也不需要调用模型。此前现代测试曾出现浏览器 Error 9，原因未确定；后续通过不能证明修复了该崩溃。

## 按这个顺序测

1. **先跑自动检查。** 检出待测提交，按仓库现有依赖安装方式准备环境，运行 `npm run check` 和 `npm run verify:release`。两项都应通过，打包内容应与当前 `lib/client.js` 一致。
2. **在两个目标宿主正常安装。** 分别准备独立的官方 DSH `0.2.0-rc.2` 和 `0.2.1-rc.2` Web 环境与空测试配置，通过正常插件安装流程装入同一份当前候选。记录宿主版本、Git 提交和 bundle SHA-256。不要复用别的任务的运行实例；安装或下载失败就报告阻塞。下列第 3–5 项在两个宿主执行，第 6 项在新版执行。
3. **检查“全文”和“已加载”不是同一个数。** 用仓库 `scripts/compat/synthetic-history.mjs` 的 `seedHistory` 在自己的隔离环境准备80轮已结束的假对话。搜索 `FIND_ALL_A_USER_`：全文应有80处；如果页面只加载最后25条，已加载模式应有25处。再搜索 `FIND_ALL_A_REPLY_`，全文应有80处；搜索 `FIND_ALL_A_`，应有160处。
4. **检查跳转和高亮。** 在全文结果里跳到第一条用户消息和第一条助手回复。页面应先加载旧消息，再显示001并准确高亮查询文字。等待动作完成后再检查，不能只看刚点击时的结果；不能跳错消息、停在加载中或出现导航失败提示。
5. **检查切换和取消。** 搜索时换词、关闭搜索、切到另一条假会话再回来。旧结果不能继续滚动页面或高亮新会话。再搜索应得到对应会话的正确结果。
6. **复查现代显示规则时，使用假数据。** 文件引用应按实际显示的文件名找到。两条默认遮挡的假密钥应有2处；手动展开第一条后总数仍为2，第一条旧高亮被清掉并给出提示，第二条仍能跳转。全文不能搜到隐藏的原文片段；已加载模式可以找到手动展开的那一条。切走再回来应重新遮挡并恢复正常定位。此项须用支持这些显示规则的宿主和真实 Chat 消息，不能用独立演示组件代替。安装不兼容就报告，不强行绕过。
